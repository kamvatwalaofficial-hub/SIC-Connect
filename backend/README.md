# SIC Connect — Backend API

ASP.NET Core Web API (.NET 8) for the SIC Connect alumni ecosystem. Layered
Clean / N-tier architecture in a single project; EF Core 8 (code-first) over SQL Server;
stateless JWT bearer auth with BCrypt password hashing.

## Layers

```
SicConnect.Api/
├── Controllers/            REST endpoints — thin, one per module
├── Application/            Use-case logic
│   ├── Services/           Business logic per module
│   ├── Dtos/               Request/response contracts (never raw entities)
│   ├── Interfaces/         Service + infrastructure abstractions
│   ├── Validators/         FluentValidation rules
│   └── Common/             Mapping, CurrentUser, AppException
├── Domain/                 Entities + Enums (pure C#)
├── Infrastructure/         AppDbContext, Security (JWT, BCrypt)
├── Middleware/             Global exception handling
├── Extensions/             DI registration (composition helpers)
├── Program.cs              Composition root — DI, auth, CORS, Swagger
└── appsettings.json        Connection string, JWT, CORS, seed settings
```

Dependencies point inward: `Controllers → Application → Domain`, with `Infrastructure`
implementing Application interfaces. Cross-cutting concerns (exception handling, JWT
middleware, CORS, Swagger) are wired in `Program.cs`.

## Prerequisites

- .NET 8 SDK
- SQL Server (LocalDB, Express, Docker, or Azure SQL)

## Configuration

No secrets are stored in this repository. `appsettings.json` holds safe defaults only:
the JWT signing secret is empty and must be supplied locally, and demo seeding is
switched on only in `appsettings.Development.json`.

| Key | Purpose |
| --- | --- |
| `ConnectionStrings:DefaultConnection` | SQL Server connection string (defaults to a local SQL Express instance) |
| `Jwt:Secret` | Signing key, **at least 32 characters**. The API refuses to start without it |
| `Jwt:Issuer` / `Jwt:Audience` / `Jwt:ExpiryMinutes` | Token parameters |
| `Cors:AllowedOrigins` | Frontend origins allowed to call the API |
| `Seed:Enabled` / `Seed:AdminEmail` / `Seed:AdminPassword` | Startup seed of an admin and demo data (Development only) |

Set the secret (and, if needed, your own connection string) with .NET user-secrets, which
keeps them outside the project folder:

```bash
cd backend/SicConnect.Api
dotnet user-secrets init
dotnet user-secrets set "Jwt:Secret" "$(openssl rand -base64 48)"
dotnet user-secrets set "ConnectionStrings:DefaultConnection" "Server=YOUR-SERVER;Database=SicConnect;Trusted_Connection=True;TrustServerCertificate=True"
```

On Windows without OpenSSL, any random string of 32+ characters works, for example one
generated by a password manager. In a hosted environment, use environment variables
(`Jwt__Secret`, `ConnectionStrings__DefaultConnection`) or a secrets vault instead.

## Run

```bash
dotnet restore
dotnet tool install --global dotnet-ef      # once
dotnet ef database update                   # applies the included migrations
dotnet run
```

On startup the app applies migrations (or creates the schema if none exist yet) and seeds
a default admin plus sample data. Swagger UI: `https://localhost:5001/swagger`.

### Seeded demo accounts (Development only)

| Role | Email | Password |
| --- | --- | --- |
| Admin | `admin@sicconnect.example` | `Admin#12345` |
| Mentor | `mentor@sicconnect.example` | `Mentor#12345` |
| Alumni | `alumni@sicconnect.example` | `Alumni#12345` |

> These are fictional demo accounts created only when `Seed:Enabled` is true (Development). They use the reserved `.example` domain and never reach a real mailbox.

## API reference

Base path `/api`. All responses are JSON. Errors use a consistent `{ "error", "details" }`
shape. Protected endpoints require `Authorization: Bearer <JWT>`.

| Method | Endpoint | Access | Purpose |
| --- | --- | --- | --- |
| POST | `/api/auth/register` | public | Create an alumni account, receive a JWT |
| POST | `/api/auth/login` | public | Authenticate, receive a JWT |
| GET | `/api/profiles/me` | auth | Current user's profile |
| PUT | `/api/profiles/me` | auth | Update own profile (skills/certs replace) |
| GET | `/api/directory` | auth | Search alumni — `?skill=&cohort=&location=&industry=&employmentStatus=&mentorsOnly=&q=&page=&pageSize=` |
| GET | `/api/opportunities` | auth | List opportunities |
| GET | `/api/opportunities/{id}` | auth | Get one opportunity |
| GET | `/api/opportunities/recommendations` | auth | **AI** opportunity recommendations (heuristic) |
| POST | `/api/opportunities` | Admin | Publish an opportunity |
| DELETE | `/api/opportunities/{id}` | Admin | Delete an opportunity |
| POST | `/api/opportunities/{id}/apply` | auth | Apply to an opportunity |
| GET | `/api/opportunities/{id}/applications` | Admin | Applications received for an opportunity |
| GET | `/api/applications/me` | auth | The caller's applications |
| PUT | `/api/applications/{id}/status` | Admin | Update an application's status |
| DELETE | `/api/applications/{id}` | auth | Withdraw own application |
| GET | `/api/networking/connections` | auth | List connections & mentorship requests |
| POST | `/api/networking/connections` | auth | Send a connection / mentorship request |
| POST | `/api/networking/connections/{id}/respond` | auth | Accept or decline a request |
| DELETE | `/api/networking/connections/{id}` | auth | Remove a connection |
| GET | `/api/networking/suggestions` | auth | **AI** networking suggestions (heuristic) |
| GET | `/api/notifications` | auth | Recent notifications |
| GET | `/api/notifications/unread-count` | auth | Unread count (header badge) |
| POST | `/api/notifications/{id}/read` · `/api/notifications/read-all` | auth | Mark read |
| GET | `/api/events` | auth | Browse events |
| GET | `/api/events/{id}` | auth | Get one event |
| POST | `/api/events` | Admin | Create an event |
| POST | `/api/events/{id}/register` | auth | Register to attend |
| DELETE | `/api/events/{id}/register` | auth | Cancel registration |
| GET | `/api/projects` | auth | List own showcase projects |

| GET | `/api/analytics/summary` | Admin | Aggregated dashboard metrics |

## Roles

`Alumni` · `Mentor` · `Admin`. The role travels in the JWT and drives
`[Authorize(Roles = "Admin")]` policies. New registrations are `Alumni`; an admin promotes
users via `/api/admin/users/{id}/role`.
